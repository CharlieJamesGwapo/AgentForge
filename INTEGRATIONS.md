# Integrations

Model inference is optional. Deterministic local commands still need no provider, credentials or network permission. Configure a provider entry with an explicit model and select its id for each request; there is no default model, automatic retry or provider fallback.

| Adapter     | Implemented protocol                                                              | Credentials                                                         | Verification evidence                                            |
| ----------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `local`     | Configuration, storage, skills, prompt transformations, graph and approved checks | None                                                                | Local engine and CLI tests                                       |
| `openai`    | Responses text, SSE and strict schema output; models endpoint connection check    | `OPENAI_API_KEY` or explicit credential environment reference       | Local HTTP contract tests; no paid/live-account calls            |
| `anthropic` | Messages text, SSE and schema output; models endpoint connection check            | `ANTHROPIC_API_KEY` or explicit credential environment reference    | Local HTTP contract tests; no paid/live-account calls            |
| `ollama`    | `/api/chat` text, NDJSON and schema output; `/api/tags` installed-model check     | None by default; optional explicit credential environment reference | Local HTTP contract tests; no real daemon/model inference tested |

The local runtime remains listed in `adapters`. Optional model adapters are activated by entries in `providers`; their availability and credentials are reported separately. This preserves existing schema-v1 configuration. Old files load with `providers: []` and `permissions.allowNetwork: false` without being silently rewritten.

`provider list`, `provider check <id>`, `status` and `doctor` are offline. `available` with `connection: not-checked` means configuration readiness only. `provider check <id> --connect --approve-network` performs one non-inference model-list request if network permission is enabled. Hosted model lists establish endpoint/auth access, not inference permission for a specific model. Ollama also checks that the configured model is present; it never downloads a model.

Generation requires `prompt --model --provider <id> --task <text> --approve-network` plus `permissions.allowNetwork=true`. The explicit task and any selected output schema are sent; there is no implicit source, context, skill, conversation or environment upload. Hosted credentials are sent in authentication headers to the configured endpoint. Review custom endpoints carefully.

All three adapters support cancellation, bounded timeouts/responses and native usage counters when present. `finishReason` distinguishes completed, length-limited and refused results; partial/refused generation exits 4. Missing or invalid usage is `unavailable`, not a token estimate. Anthropic total input tokens include raw input plus cache-read/cache-creation counters, also reported separately when present. Model-returned names are preserved because server aliases can report a different concrete snapshot; the request always uses the exact configured model.

All three adapters support streaming and the shared portable structured-output subset, with local validation before data is returned. They also support bounded ordinary and streaming client tool conversations, optionally combined with locally validated structured final answers. Optional local tool-result schemas apply identically across all three protocols and both modes; fixed CLI tools provide default schemas. Result contracts are stripped from native declarations and successful results must validate before and after data redaction. Adapters never execute tools; an independent host registry requires explicit approval for each immutable batch. The CLI exposes package summary, bounded project search/read, read-only Git, edit previews and preconfigured verification checks. Every execution batch needs exact approval; process tools need process permission. See [tool invocation](docs/integrations/tool-invocation.md) and [streaming and structured output](docs/integrations/streaming-structured.md). Coding-host installation and external agent dispatch remain unavailable. Capability flags describe the implemented wrapper, not every upstream feature. Generated text is untrusted output and is never executed.

See [provider setup](docs/integrations/providers.md), [adapter contract](src/adapters/types.ts) and [adapter development](docs/integrations/adapter-development.md). The native protocols follow the official [OpenAI text guide](https://developers.openai.com/api/docs/guides/text), [Anthropic Messages reference](https://platform.claude.com/docs/en/api/messages/create) and [Ollama chat reference](https://docs.ollama.com/api/chat). These references do not establish that any particular account or local machine can access a model.

The provider-neutral `task` runtime composes these same sessions with a refined prompt, optional explicit checkpoint reference, total deadline/call/output limits and cumulative native usage. `tools run` remains the lower-level explicit-prompt interface; `run` remains local check orchestration. See [task runtime](docs/features/task-runtime.md) and [project file tools](docs/integrations/project-files.md). No live-provider compatibility claim is added; hosted account/model support and real Ollama inference remain unverified.

Optional [built-in orchestration](docs/features/orchestration.md) uses these adapters for a strict planner and at most two bounded worker conversations. Planner and executor providers/models are explicit configuration, with no vendor identity embedded in the engine. Permissions are snapshotted, tools are scoped and approval is central. This is built-in conversation scheduling, not a claim that a vendor or external coding host supports native subagent dispatch. [Edit application](docs/integrations/project-edits.md) remains unavailable before any write on the Node backend; [Git inspection](docs/integrations/git-inspection.md) works offline after exact approval.

Credential safety applies to both ordinary and streaming conversations: selected environment references are resolved explicitly, reports sanitize configured credentials, and schema-bound values with credential-bearing keys or typed primitive leaves are withheld. Model identifiers reject terminal controls before normalization. These checks preserve native request model selection and native usage counters; redacted diagnostic names are presentation only.

The installed terminal suite (`npm run test:terminal`, POSIX/Python 3) exercises all three native protocols for approved, denied and cancelled tool workflows, with checkpoint context and structured finals in ordinary/streaming tasks. These local fixture results do not establish live model availability or vendor-native multi-agent dispatch. See [testing evidence and platform scope](docs/development/testing.md).
