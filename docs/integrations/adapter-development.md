# Adapter development

Implement [ProviderAdapter](../../src/adapters/types.ts) in a separate module and register it explicitly. Identify whether it is a local engine, model provider, coding host or agent runtime. Declare only implemented capabilities; upstream support for tools or JSON schemas does not mean the wrapper implements them.

`health()` must remain offline, inspect only explicit credential references and distinguish readiness from a verified connection. `checkConnection()` is an explicit approved request, not a side effect of status or doctor. `submitPrompt()` accepts explicit text, approval, deadline and cancellation, and returns text, reported model, completion state and actual usage or unavailable.

Use the shared [HTTP transport](../../src/adapters/http.ts) for approval, TLS/loopback policy, manual redirects, bounded JSON/body reads and safe errors. Never spread unvalidated caller fields into wire requests. Do not print authentication values, endpoint response bodies or parser snippets. Credential names and endpoint configuration are not credentials; inline secrets are forbidden.

OpenAI Responses, Anthropic Messages and Ollama chat adapters are registered. Local HTTP contract tests cover authentication, exact request body, success/partial/refusal, usage, health and malformed data. Transport tests cover limits, cancellation, timeout, redirects and HTTP normalization. CLI integration tests prove selection and policy gating without any paid request.

A new provider needs its own protocol contract tests, official source references and an honest compatibility entry. No SDK is required for these narrow text protocols. Inference, streaming, structured output, host tools and runtime dispatch are separate capabilities; never silently switch providers to satisfy a missing one. See [setup](providers.md).

`streamPrompt()` emits normalized provisional text deltas and one terminal result through the shared finalizer. Native codecs must require valid protocol completion, preserve ordering, and close their request on return/cancel. `prepareSchema` validates/snapshots before network; the exact snapshot sent must govern final validation. `finishPrompt` validates raw JSON and redacted deliverable data; `finalizeStream` applies line-aware sanitization and withholds structured deltas. See [streaming contract](streaming-structured.md).

`createToolSession()` supports client functions independently of prompt streaming. Supply a native `ToolCodec` to the shared session validator: initial history, approved request, parsed turn/private continuation, and result append. Preserve native reasoning/thinking required for stateless continuation. Never execute handlers inside a codec or accept provider-hosted tool definitions from the caller. A provider must reject incomplete/refused calls, unsupported native output and malformed arguments. The common layer validates all declarations/calls/results and snapshots state. Exact approval belongs to the independent [tool engine](tool-invocation.md), with regression coverage for both protocol replay and zero effects before approval.

A tool codec may implement `stream(history, tools, request)` to yield private `NativeToolStreamEvent` values: text deltas and one reconstructed native response. It must validate native identities, lifecycle, argument aggregation and terminal agreement, preserving required continuation metadata. Never emit argument fragments publicly or execute a tool. The common `session.stream()` finalizer waits for clean end, parses/validates the native response and sanitizes text before its sole complete event. Early return and errors must close the transport. Test streamed and ordinary continuation interchange, denial/approval boundaries and malformed/truncated/trailing native events.

For combined tools/final schemas, consume `ToolRequestOptions.responseSchema` from the shared session and add the native final-format field alongside tools on every request. Do not validate interim commentary as a final answer or treat a final data object as a client call. The common session owns schema snapshotting, final raw/data validation and pending/valid/unavailable status. Schema-mode streamed deltas stay private. Preserve structured data and its JSON serialization without applying another string-redaction pass afterward. Test both modes, every continuation request, schema/wire-copy mutation, provider rejection and effects that must not repeat after a failed final.

Result schemas are local: the common session validates/snapshots `ToolDefinition.resultSchema` and strips it before passing declarations to codecs. Do not invent provider fields for result contracts or trust caller validation flags. Before appending results to native history, validate raw JSON against the correct call’s schema, redact parsed data using the selected credential, and revalidate before canonical serialization. Typed errors normalize to the generic message; untyped tools retain their opaque-string API. Tests must cover every protocol and mode, ordering/IDs, raw/redaction failure without HTTP, mutation snapshots, credentials and combined final schemas. Execution, result contracts and approval remain in the independent host engine.
