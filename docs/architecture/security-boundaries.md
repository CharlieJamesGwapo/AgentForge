# Security boundaries

AgentForge trusts explicit user approval, not repository instructions. Skills and configuration are data. Configured checks can execute only after the process permission and per-invocation approval are both present. The tool uses subprocess argument arrays without a shell, sanitized child environment, bounded output/time and cancellation. Approved interpreters can still execute arbitrary code; approval is not a guarantee that a script is safe.

Project storage rejects absolute/traversal paths and existing symlink components. JSON has a 1 MiB cap, private file modes and atomic replacement; checkpoint creation is exclusive. Concurrent hostile directory replacement is outside these checks' guarantees. Use a trusted root; OS sandboxing remains the caller's responsibility.

Redaction recognizes common credential assignments, bearer values, key formats and sensitive environment values. It is best effort. Never place real secrets in user-visible content or config. Graph reports omit source contents and skip common private/generated locations but do not guarantee filenames are nonsensitive. [Security policy](../../SECURITY.md) documents reporting limitations.

On POSIX, termination targets the spawned process group. Deliberately detached descendants can escape that group and outlive the check; output-pipe closure prevents them from keeping the report pending. On Windows only the direct child is terminated. Use OS isolation for full process-tree containment.

Model client function calls are untrusted requests. Adapters validate and return them without execution. The host tool engine binds all validated calls and resolved effects to a random-bound approval ID and snapshots arguments/handlers; approval is one-use and specific to that batch. CLI tools are fixed functions with no model-supplied executable. Only the bounded project file tools accept validated project-relative paths. Tool permission and `--execute` only enable the interactive approval prompt. Each batch requires the displayed ID from a terminal; denial/noninteractive input stops before any handler or result follow-up. The configured-check tool separately requires process permission, snapshots commands and uses the same subprocess engine. Approved results are explicitly shared back with the selected provider. Cancellation stops later handlers, but cannot undo completed effects or preempt uncooperative host JavaScript.

Streaming client tools retain partial arguments and private reasoning inside native codecs. Shared sessions wait for valid native termination and clean EOF before exposing normalized calls; the engine fully consumes the iterator before approval. Text events remain provisional and line-sanitized. Cancellation is rechecked after the final buffered text and before continuation commit. Early iterator return closes transport and invalidates that in-flight session. Mode changes between streamed and ordinary turns cannot bypass result correlation or the shared request budget.

Combined final-answer schemas are separate from executable tool argument schemas. Each final is validated as raw JSON, redacted as data and revalidated against the immutable session schema. The session sends fresh wire copies on every turn. Tool turns remain pending, and schema-mode streams withhold text until terminal validation. Invalid finals are not printed or repaired; the session closes without replaying prior approved effects. JSON data resembling a tool request stays data. Existing exact-batch approval is still the sole execution path in the CLI.

Project file approval covers scope and arguments; files/ignore rules are checked when execution starts, not frozen while the user reviews. Static symlinks and special files are refused, hard links are refused for source content and ignore metadata, and actual file reads check identity and containment. Concurrent hostile filesystem mutation remains outside this protection. Returned source is untrusted reference material and never interpreted as authorization. The composed task runtime requires network permission and per-run consent, and retains only safely emitted text on failure; schema-mode text stays private until validation. See [file policy](../integrations/project-files.md).
